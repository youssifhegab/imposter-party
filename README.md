# Imposter Party Game

Monorepo:

- `server/` — Kotlin + Spring Boot 3 (JDK 21, Gradle Kotlin DSL)
- `mobile/` — Expo (SDK 58) + Expo Router + TypeScript
- `docs/protocol.md` — the client/server contract

## Run locally

```sh
# 1. Postgres (Docker Desktop must be running)
docker compose up -d

# 2. Server on :8090 (Flyway migrates on startup)
cd server && ./gradlew bootRun

# 3. App
cd mobile && npx expo start
```

To play, open the app in Expo Go on each phone (scan the QR code from `npx expo start`). The phones and the
Mac must be on the same Wi-Fi. One phone creates a party, the others join with the 5-letter code.

The app reaches the server at `http://<metro-host-ip>:8090`, so a phone on the same Wi-Fi works with no config.
Override with `EXPO_PUBLIC_API_URL=http://host:port npx expo start`.

### Previewing screens in a browser

`npx expo start --web` runs the app in a browser too (no haptics or confetti there). The dev-only route
`/dev` shows any game screen with sample data, without playing a game, for example:

- http://localhost:8081/dev?phase=VOTING
- http://localhost:8081/dev?phase=REVEAL&imposter=1&lang=ar&theme=light

Flags: `phase` (LOBBY, REVEAL, CLUES, DISCUSSION, VOTING, REVOTE, GUESS, RESULTS, FINAL), `lang=ar`,
`theme=light`, `imposter=1`, `admin=0`, `myTurn=1`, `voted=1`, `prompted=1` (GUESS), `waiting=1`.

### Sounds and confetti

They are generated by scripts, not downloaded, so they can be tweaked and rebuilt:
`node scripts/make-sounds.mjs` writes `assets/sounds/*.wav`, and `node scripts/make-confetti.mjs` writes
`assets/lottie/confetti.json`.

## Words

All categories and words live in `server/src/main/resources/content/words.json`. Edit it and restart the server:
Flyway's repeatable migration `R__Content` re-syncs Postgres whenever the file changes. Removed words are marked
inactive, so ids of the remaining words never change. `./gradlew test` checks the file (12 categories, 150+ words per
language, no duplicates across categories, no two words close enough that a typo of one counts as the other).

To avoid repeats across parties, each phone remembers the last 300 words it played and sends their ids when it
connects. New rounds skip any word someone in the room saw recently, and only fall back to those once a category
runs out. Word ids staying stable is what makes this work, so never renumber words.
